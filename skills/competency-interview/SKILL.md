# 역량별 면접

먼저 `../../AGENTS.md`, `../../docs/data-contract.md`, `../../docs/terminology.md`와 선택된 면접관 스타일 파일을 읽는다.

대상 역량을 사용자의 요청, 채용 기준 또는 판단 근거가 부족한 영역에서 정한다. 스타일의 관심 영역이 평가 기준을 대체하지 않게 한다.

프로덕트 디자이너의 AI 역할 변화, 협업 중 의견 충돌 또는 문제 해결 과정 질문을 다룰 때 `../../rubric/question-guides/product-designer-core.yaml`을 읽는다. 답변 심화 코칭에서는 추가로 `references/product-designer-core-coaching.md`를 읽고, 평가에서는 코칭 참고 자료를 읽거나 사용하지 않는다.

협업 역량을 다룰 때 `../../rubric/evidence-guides/collaboration.yaml`을 읽는다. 답변 심화 코칭에서는 `references/collaboration-coaching.md`도 읽고, 평가에서는 코칭 참고 자료를 사용하지 않는다.

AI를 활용한 디자인 경험을 다룰 때 `../../rubric/evidence-guides/ai-assisted-work.yaml`을 읽는다. 답변 심화 코칭에서는 `references/ai-assisted-work-coaching.md`도 읽고, 평가에서는 코칭 참고 자료를 사용하지 않는다.

## 진행 규칙

- 행동과 경험을 확인할 수 있는 질문을 한 번에 하나씩 한다.
- 하나의 사례만으로 일반화하지 말고 필요하면 다른 맥락의 사례를 확인한다.
- 가상 상황 답변과 실제 행동 근거를 구분한다.
- 답변의 유창함, 긴장, 말투를 역량으로 평가하지 않는다.
- 이미 충분한 판단 근거가 있으면 다른 부족한 영역으로 이동하거나 종료한다.
- 매 답변 직후 이어하기 정보를 저장한다.
- 특정 문장, STAR 형식, 방법론 이름 또는 유행어가 포함됐다는 이유로 높게 평가하지 않는다. 실제 상황, 판단, 행동과 결과의 연결을 확인한다.

평가와 코칭의 힌트·피드백·근거 사용 규칙은 공통 정책을 따른다.
