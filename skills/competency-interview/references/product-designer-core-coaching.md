# 프로덕트 디자이너 핵심 질문 코칭

이 자료는 답변 심화 코칭에서만 사용한다. 내용을 그대로 외우게 하지 말고 사용자의 실제 경험을 구체화한다. 여기서 만든 답변은 채용 평가 근거로 사용하지 않는다.

## AI와 디자이너의 역할 변화

다음 순서로 답변을 구성하도록 돕는다.

1. AI로 변화할 것으로 보는 구체적인 디자인 업무
2. 사람이 계속 책임져야 한다고 보는 판단
3. AI를 직접 사용하며 확인한 가능성과 한계
4. 앞으로 확장하려는 자신의 전문성 또는 역할
5. 다음에 직접 실행할 학습이나 실험

“변화에 적응하겠다”는 선언만 있다면 실제 사용 경험, 검토 행동과 구체적인 확장 방향을 질문한다.

## 협업 중 의견 충돌

다음 순서로 답변을 구성하도록 돕는다.

1. 충돌이 발생한 상황
2. 서로 달랐던 목표와 제약
3. 상대 입장을 이해하기 위해 한 행동
4. 함께 합의하거나 선택한 판단 기준
5. 본인이 바꾼 생각 또는 수행한 행동
6. 결정의 결과와 다음 협업에서 달라진 점

누가 이겼는지가 아니라 어떤 기준으로 제품에 적절한 결정을 만들었는지 드러나야 한다.

## 문제 해결 과정의 고민

다음 흐름을 사용하되 모든 항목을 억지로 채우지 않는다.

```text
초기 문제 인식
→ 가설
→ 확인 방법
→ 새롭게 발견한 내용
→ 바뀐 판단
→ 실행한 변경
→ 결과
→ 학습
```

리서치 방법이나 지표의 이름보다 무엇을 새롭게 알았고 그 결과 어떤 판단을 바꿨는지 구체화한다. 성공한 결과가 없어도 실패에서 확인한 내용과 후속 결정을 명확히 설명할 수 있다.

## 피드백 방식

답변 후 다음 순서로 피드백한다.

1. 답변에서 이미 구체적인 부분
2. 듣는 사람이 추정해야 하는 부분
3. 판단을 입증할 수 있는 추가 맥락
4. 권장 답변 구조
5. 사용자가 자신의 언어로 다시 답할 기회

완성 문장을 먼저 제공하지 않는다. 예시가 필요하면 사용자의 경험과 명확히 구분되는 짧은 가상 사례만 제공한다.
