# 도움말

`references/project-guide.md`를 끝까지 읽고 사용자의 질문 범위에 맞춰 설명한다. 현재 구현 상태나 파일을 묻는 경우 `../../AGENTS.md`와 관련 파일도 직접 확인한다.

## 설명 원칙

- 사용자가 개발 구조를 묻지 않았다면 기능과 사용 경험부터 설명한다.
- `../../docs/terminology.md`의 사용자용 표현을 사용한다.
- 내부 ID, YAML, 스키마, 프롬프트 같은 기술 용어는 필요한 경우에만 풀어서 설명한다.
- 기능을 나열하는 데 그치지 말고 언제 사용하고 어떤 결과를 얻는지 설명한다.
- 사용자가 바로 시도할 수 있는 자연어 요청 예시를 함께 제공한다.
- 아직 구현되지 않은 기능을 구현된 것처럼 설명하지 않는다.
- 실제 지원자 데이터가 로컬에 저장되고 Git에는 올라가지 않는다는 점을 개인정보 관련 질문에서 명확히 안내한다.

## 요청별 응답

- 전체 소개를 요청하면 프로젝트의 목적, 주요 사용자, 가능한 작업, 전체 사용 흐름, 평가와 코칭의 차이, 면접관 스타일, 기록과 개인정보 순서로 설명한다.
- 무엇부터 해야 하는지 묻는다면 목적에 맞는 첫 요청 하나와 선택 가능한 다음 작업을 제안한다. 고정된 순서를 강요하지 않는다.
- 특정 기능을 묻는다면 해당 기능의 입력, 진행 방식, 결과, 주의점을 설명한다.
- 기술 구조를 묻는다면 Codex 대화, 독립 스킬, 로컬 기록, 작업공간 분리를 설명하고 관련 파일 경로를 제공한다.
