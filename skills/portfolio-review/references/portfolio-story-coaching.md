# 포트폴리오 설명 코칭

포트폴리오 설명을 개선하거나 답변 심화 코칭을 할 때만 사용한다. 여기서 다듬은 표현은 채용 평가 근거로 사용하지 않는다.

## 기본 흐름

```text
문제와 중요성
→ 문제라고 판단한 근거
→ 팀 구성과 나의 역할
→ 검토한 대안
→ 선택 기준과 포기한 가치
→ 최종 결정
→ 결과와 학습
```

시각 자료와 공간이 제한된 경우 모든 과정을 길게 보여주기보다 프로젝트의 판단을 가장 잘 드러내는 순간을 선택한다.

## 문제 설명

다음 질문으로 일반적인 표현을 구체화한다.

1. 누가 어떤 상황에서 어려움을 겪었나요?
2. 무엇을 근거로 중요한 문제라고 판단했나요?
3. 사용자와 제품에는 어떤 영향을 주었나요?
4. 이번 프로젝트가 다룬 범위는 어디까지였나요?

정량 수치는 출처와 수집 방법을 설명할 수 있을 때 사용한다. 숫자가 없더라도 구체적인 관찰과 문제의 영향을 설명할 수 있다.

## 역할 설명

1. 팀에는 어떤 역할이 있었나요?
2. 본인이 직접 책임진 범위는 무엇이었나요?
3. 함께 결정한 부분은 무엇이었나요?
4. 다른 사람이 주도하고 본인이 기여한 부분은 무엇이었나요?
5. 본인의 판단으로 달라진 결정은 무엇이었나요?

기여율 숫자를 먼저 만들지 말고 실제 책임, 행동과 결정을 설명한다.

## 대안과 선택

1. 최종안 외에 검토한 방향은 무엇이었나요?
2. 각 방향의 장점, 단점과 제약은 무엇이었나요?
3. 무엇을 유지하고 무엇을 포기해야 했나요?
4. 최종 선택에 사용한 기준은 무엇이었나요?
5. 새로운 정보 때문에 판단을 바꾼 부분이 있었나요?

중간 시안을 많이 보여주는 것이 목적이 아니다. 최종 결과가 나온 이유를 가장 잘 설명하는 대안과 판단만 선택한다.

## 피드백 방식

1. 문제, 역할과 결정 중 이미 분명한 부분
2. 독자가 추정해야 하는 부분
3. 추가로 확인할 실제 경험
4. 포트폴리오에 남길 핵심 장면
5. 권장 설명 흐름
6. 사용자가 자신의 언어로 다시 작성할 기회

NDA가 있는 경우 공개할 수 없는 화면이나 수치를 요구하지 않는다. 공개 가능한 범위에서 문제의 성격, 담당 역할, 판단 기준과 학습을 설명하도록 돕는다.
